# 把模拟电压变成串口数据：STM32 ADC采样与均值滤波

> 源码：[github.com/NaHSIT/STM32ZET6Project/tree/main/projects/07-adc-voltage-monitor](https://github.com/NaHSIT/STM32ZET6Project/tree/main/projects/07-adc-voltage-monitor)

7月17日，前面的项目处理的都是0和1，我想让STM32开始认识连续变化的真实信号。于是把电位器输出接到`PA1`，每秒采一次电压，通过串口打印出来。

ADC读数本身很容易拿到，真正值得处理的是时钟、采样时间、校准和抖动。屏幕上一个不停跳的三位小数没有多少意义，稳定、可解释的数据才有用。

---

## 1. 硬件组成

- STM32F103ZET6的ADC1。
- `PA1`对应`ADC_Channel_1`。
- 10kΩ电位器，两端接3.3V和GND，中间滑臂接PA1。
- USART1把结果发到电脑。
- TIM2每秒产生一次采样节拍。

输入电压必须处于0-3.3V，不能因为ADC“只是输入”就直接接5V信号。模拟地也要和开发板共地。

---

## 2. ADC时钟不能直接用72MHz

STM32F1的ADC时钟有上限。我把PCLK2用六分频降到12MHz：

```c
RCC_ADCCLKConfig(RCC_PCLK2_Div6);
```

PA1配置为模拟输入，避免数字输入缓冲参与。ADC使用独立、单通道、单次转换和软件触发，每次读取前选择通道并启动转换。

初始化后还要执行复位校准和启动校准。刚上手时我漏掉校准，低电压区域的偏差尤其明显。它不能消除参考电压误差，但能减小ADC内部偏移。

---

## 3. 十次平均换来稳定读数

单次采样会受电源、导线和手碰电位器影响，最低几位一直跳。我没有一上来加复杂滤波，而是连续采10次求平均：

```c
for (i = 0U; i < times; ++i) {
    sum += ADC1_Get(channel);
}
return (uint16_t)(sum / times);
```

12位ADC输出0-4095，按3.3V参考电压换算：

$$V=\frac{ADC\times3.3}{4095}$$

平均后串口显示稳定了很多，旋转电位器时变化仍然足够快。对于每秒一次的监视器，十次阻塞采样的开销可以忽略。

---

## 4. 数字稳定不代表电压绝对准确

我拿万用表对比后发现，ADC显示2.50V时，实际电压会差几十毫伏。原因不是公式错了，而是公式默认参考电压正好3.300V，开发板实际供电并没有这么理想。

如果要提高绝对精度，可以测量真实VDDA后替换3.3，或者读取内部参考源反推供电电压。当前项目更关注采样流程和相对变化，所以保留了简单换算，但把这个误差来源写进了说明。

---

> ADC让我第一次直观看到，物理世界不是干净的整数。采样值会抖，参考电压会偏，线也会带来噪声。代码要做的不是假装这些问题不存在，而是知道误差从哪里来，并选一个够用的处理办法。
