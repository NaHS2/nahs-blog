# 七人表决电路：用 51 单片机实现一个简单的投票器

大二暑假，用 51 单片机做了一个**七人表决电路**。七个拨动开关代表七个人投票，两个数码管分别显示赞成票和反对票，绿 LED 亮表示通过（赞成 ≥ 4），红 LED 亮表示否决。

这项目规模很小，但它是数字逻辑和单片机编程之间的一座桥梁——纯逻辑门也能实现同样的功能，但用单片机几行代码就搞定了。

---

## 1. 硬件组成

- **51 单片机（AT89C51 / STC89C52）**
- **7 个拨动开关** — 接 P1.0 ~ P1.6，拨到 ON 表示投赞成
- **2 个共阳数码管** — P0 口段选，P2.2/P2.3 位选
- **绿 LED（P2.0）** — 表决通过指示灯
- **红 LED（P2.1）** — 表决否决指示灯

---

## 2. 程序逻辑

整体结构非常直接：

**读取投票。** 读 P1 口低 7 位，每一位代表一个开关。遍历 7 个 bit 统计有多少个 1，就是赞成票数。反对票 = 7 - 赞成票。

**表决判断。** 赞成票 ≥ 4，绿灯亮、红灯灭；否则红灯亮、绿灯灭。

**数码管显示。** 两个数码管轮流显示赞成数和反对数。每次显示前先消隐（关掉所有段和位选），再送段码、开位选。消隐是为了防止上一个数字的残影干扰下一个字符——这叫做"动态扫描消隐"，是数码管驱动的基本操作。

**循环计时。** 用计数器而非定时器中断——主循环跑 1000 次为一轮读取开关，100 次为一轮刷新显示。频率不用很精确，肉眼看不出延迟就行。

---

## 3. 数码管动态扫描

两个数码管共用一组段选线（P0 口），一次只能亮一个。要让两个管子看起来"同时在显示"，需要交替点亮——先显示赞成数再显示反对数，切换频率够高（>50Hz）人眼就感觉不到闪烁。

关键的消隐代码：

```c
// 切换显示前先消隐
DIG1 = 1;    // 关十位位选
DIG2 = 1;    // 关个位位选
P0 = 0xFF;   // 关所有段
delay_us(50); // 消隐停留

// 然后送新数据
P0 = SEG_CODE[approve_count];
DIG1 = 0;    // 开十位位选
```

如果不消隐直接切位选，上一个数字会瞬间残留在下一个位置上，肉眼虽然难以察觉但数码管亮度会不均匀。

---

## 4. 如果用纯硬件做

这个功能用纯数字逻辑芯片也能实现：

- 7 个开关 → 7 路加法器（74LS283 × 2）做二进制加法
- 加法结果 → 比较器（74LS85）判断 ≥ 4
- 比较器输出 → 驱动两个 LED
- BCD 码 → 74LS47 译码器 → 数码管

单片机方案代码 30 行，纯硬件方案要七八个芯片加一堆连线。两种思路各有用处——硬件方案快、可靠、不需要编程；单片机方案灵活、可扩展、改逻辑只需要改代码。这次用单片机做，本质上是拿软件替代了一堆逻辑门。

---

## 5. 修改到最终版本前的插曲

最初在 Proteus 仿真里，数码管显示一直缺笔画。排查发现是 P0 口没有上拉电阻——51 单片机的 P0 口是开漏输出，驱动共阳数码管时外部必须接上拉，否则高电平根本输出不了。Proteus 里拖几个 10kΩ 排阻接上就正常了。

另外在调试时发现拨动开关偶尔会读到不确定的状态——开关在 ON/OFF 之间切换的一瞬间，机械触点不是即刻稳定，而是有几毫秒到几十毫秒的抖动。51 单片机的读取速度远快于这个抖动周期，所以会读到一连串快速翻转的 0/1。解决方法很简单——不要在每个循环周期都读开关，1000 次循环读一次，频率降到大约 10Hz，自然就滤掉了机械抖动。

---

> 这个电路是数字逻辑 EDA 实验的一部分。很多人觉得"逻辑电路"和"单片机"是两个完全不相关的领域，但实际上它们解决的是同一类问题——采集输入、按规则判断、输出结果。这次用单片机替代一堆逻辑芯片来做表决，算是对"软件定义硬件"有了最初步的感知。
