# 一个按键控制LED亮度：短按调光，长按呼吸

> 源码：[github.com/NaHSIT/STM32ZET6Project/tree/main/projects/13-button-pwm-controller](https://github.com/NaHSIT/STM32ZET6Project/tree/main/projects/13-button-pwm-controller)

8月14日，我用一个小项目收尾这13篇STM32实践：只保留一枚按键和一盏LED，短按切换五档亮度，长按进入或退出呼吸模式。

硬件比前面的多外设项目少，交互逻辑却更完整。程序需要同时识别消抖、按下时长、松手事件、亮度档位和呼吸状态，不能再靠几个互相嵌套的`while`凑效果。

---

## 1. 硬件组成

- S1连接`PE4`，上拉输入，按下为低电平。
- LED1连接`PB5`，低电平点亮。
- TIM3_CH2部分重映射到PB5，输出1kHz PWM。
- 主循环每10ms运行一次交互状态机。

短按依次切换0%、25%、50%、75%和接近100%的亮度。长按1秒切换呼吸模式，再次长按退出。

---

## 2. 为什么原来的写法会吞输入

最初版本按下后用一个`while`等待松手，再用另一个`while`执行闪烁。闪烁过程中只能反复插入按键检查，逻辑越补越乱，最后甚至用`goto`跳回主流程。

它能工作，但每种状态都在占住CPU等待下一个条件。功能再加一个，嵌套就会继续变深。

我把流程改成固定10ms走一步：每轮读取当前电平，维护稳定计数和按住计数，然后立即返回主循环顶部。没有任何一次等待超过10ms。

---

## 3. 短按和长按怎样区分

按键稳定按下三轮后才算有效，随后`held_ticks`每10ms加一。达到100次，也就是约1秒时，立刻切换呼吸模式，并设置`long_press_handled`，防止继续按住时重复触发。

松手时，如果之前确实按下、又没有触发长按，就把它当作短按，切换下一档亮度。

这个设计的关键是：**长按动作发生在按住期间，短按动作发生在松手时**。两条路径天然互斥，不需要事后猜这次应该算哪一种。

---

## 4. 呼吸模式也是状态，不是循环

呼吸亮度用`breath_compare`和`breath_delta`推进。每10ms增加或减少5，到0或999时反转方向。

```c
next = (int32_t)breath_compare + breath_delta;
if (next >= PWM_ARR) {
    next = PWM_ARR;
    breath_delta = -BREATH_STEP;
}
```

主循环每次只改一点CCR，所以按键检测始终在继续。短按会退出呼吸模式并切换固定亮度，长按则保留当前亮度作为呼吸起点，视觉变化不会突然跳太远。

---

## 5. 小项目反而适合检查代码习惯

这次我统一了无符号常量、数组边界和状态变量，去掉长时间阻塞与`goto`。项目没有复杂外设互相掩盖问题，反而很适合确认接口和交互逻辑是否清楚。

从第一篇只会交替闪的两盏灯，到最后用同一盏灯表达档位和模式，硬件变化不大，我看待程序的方式已经完全不同：不再只问“效果能不能出来”，还会问“下一项功能加进来时，结构会不会垮”。

---

> 13个项目结束后，我没有把STM32“学完”，但已经建立了一条能继续往前走的路线：先理解外设，再封装接口；先处理正常路径，再补边界；最后让多个模块在同一个主循环里互不阻塞地协作。
